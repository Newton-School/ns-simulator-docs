# Compute Contention: sourcing the per-type `cpuBoundFraction`

Companion to [`compute-contention-two-tier-model.md`](./compute-contention-two-tier-model.md). That spec resolved _where_ the CPU-vs-I/O split lives (option B: a per-component-type, author-locked `cpuBoundFraction` in [`resourceDefaults.ts`](../../src/engine/catalog/resourceDefaults.ts)). This doc sources the actual numbers — one entry per debatable type, each with reasoning and a citation — so the values are defensible rather than gut-felt, and records where research **changed** the first-pass guesses.

Status: shipped 2026-09-03. The engine consumes these author-locked, per-type values in the two-tier CPU-contention model. Revising a value changes simulated service time and utilization, so it requires the migration-gate sweep.

---

## The modeling clarification research forced (read this first)

Our two-tier model splits each request's service time into "contends for a physical core" vs "multiplexes freely." The naive reading is "CPU vs I/O." Research on vector DBs and OLAP shows that is **too narrow**: the real dividing line is **does the work occupy/stall a core, or is it parked waiting somewhere a core can walk away from?**

- **CPU tier** (contends for cores) = arithmetic **and memory-bandwidth-bound work**. A vector similarity scan or an OLAP aggregation is often "memory-bound," not compute-bound — but a core stalled on RAM bandwidth is _still tied up_; it cannot go serve 31 other requests the way it can while a network read is in flight. So memory-bound work belongs in the **CPU tier** for our purposes.
- **I/O tier** (multiplexes freely) = work parked on **network or disk** waiting, where the core genuinely yields to other requests.

This is why the analytical stores get high fractions even though they're labelled "io-bound": their heavy phase stalls cores (compute + memory bandwidth), it does not yield them. This paragraph is the justification behind every Group 2 number below.

## Confidence & the empirical backstop

- **High confidence:** the 0.05 forwarders/byte-servers/messaging, the 1.0 cpu-bound tier, vector-db and data-warehouse at 0.80.
- **Medium (bands):** relational-db 0.35, serverless 0.40, the TLS-proxy 0.15 cluster — real workloads span a range; these are defensible midpoints with a documented ceiling.
- **The backstop:** none of this has to be perfect now. The **migration harness** (next plan step) re-runs the whole question bank and shows which verdicts move. A fraction that's too aggressive shows up as a question flipping for a reason that doesn't hold up, and we dial it back — so the numbers get _validated against actual questions_, not just literature.
